# Deployment guide

How the live demo of Alijenta is hosted, how to set it up from scratch and how to keep it
alive. Everything runs on free plans.

```
Visitor ──► Frontend: Vercel (static React build)        alijenta.vercel.app
               │
               ▼  HTTPS + JWT
            Backend: Render (Docker, Spring Boot)        alijenta-api.onrender.com
               │                        │
               ▼                        ▼
        TiDB Cloud Starter           Dropbox
        (MySQL-compatible DB)        (attachments, refresh token)

UptimeRobot ── every 5 min ──► /actuator/health ── e-mail if DOWN (also keeps Render awake)
GitHub Actions ── daily ─────► frontend → health → demo login → demo data
Backend ── daily 03:00 UTC ──► wipes visitor changes and reloads the demo workspace
```

| Part | Where | Free plan limits that matter |
|---|---|---|
| Frontend | Vercel | — |
| Backend | Render, `render.yaml` | 512 MB RAM, sleeps after 15 min without traffic (UptimeRobot prevents it), **no outbound SMTP** |
| Database | TiDB Cloud Starter | 5 GiB, no expiry |
| Files | Dropbox Basic | 2 GB, uploads limited to 5 MB in prod |
| Monitoring | UptimeRobot + GitHub Actions | GitHub disables scheduled workflows after 60 days without repository activity |

Setup order matters: database → Dropbox → backend → frontend → Google → monitoring.

---

## 1. Database: TiDB Cloud Starter

1. Sign up at <https://tidbcloud.com> and create a **Starter** cluster (region close to the
   backend, e.g. AWS Frankfurt `eu-central-1`).
2. Open the cluster → **SQL Editor** and run: `CREATE DATABASE alijenta;`
3. Click **Connect** → connect with **Java / JDBC** → generate a password.
4. Keep these three values for Render:

   | Render variable | Value |
   |---|---|
   | `DB_URL` | `jdbc:mysql://<HOST>:4000/alijenta?sslMode=VERIFY_IDENTITY&enabledTLSProtocols=TLSv1.2,TLSv1.3` |
   | `DB_USERNAME` | the user from the dialog, looks like `xxxxxxxx.root` |
   | `DB_PASSWORD` | the generated password |

Liquibase creates the schema and the demo workspace on the first start.

## 2. Dropbox: long-lived refresh token

A refresh token does not expire (until you revoke it); the backend uses it to get fresh
short-lived access tokens automatically.

1. <https://www.dropbox.com/developers/apps> → your app → **Settings**: copy **App key** and
   **App secret**.
2. **Permissions** tab: `files.content.write`, `files.content.read` and `account_info.read`
   must be checked (the health check uses `account_info.read`). Press **Submit** if you changed
   anything.
3. Open in the browser (replace `APP_KEY`):

   ```
   https://www.dropbox.com/oauth2/authorize?client_id=APP_KEY&response_type=code&token_access_type=offline
   ```

   Press **Allow** and copy the code shown.
4. Exchange the code for a refresh token (PowerShell, the code is valid for a few minutes):

   ```powershell
   Invoke-RestMethod -Method Post -Uri https://api.dropboxapi.com/oauth2/token -Body @{
     code = 'CODE'; grant_type = 'authorization_code'
     client_id = 'APP_KEY'; client_secret = 'APP_SECRET'
   } | Select-Object refresh_token
   ```

5. Keep `DROPBOX_REFRESH_TOKEN`, `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET` for Render.

## 3. Backend: Render

1. <https://render.com> → sign in with GitHub → **New → Blueprint** → select this repository.
   Render reads `render.yaml` and creates the `alijenta-api` web service.
2. Fill in the values Render asks for:

   | Variable | Value |
   |---|---|
   | `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | step 1 |
   | `DROPBOX_REFRESH_TOKEN`, `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET` | step 2 |
   | `SECURITY_ENCRYPTION_SALT` | a hex string; PowerShell: `-join (1..8 \| % { '{0:x2}' -f (Get-Random -Max 256) })` |
   | `TELEGRAM_BOT_TOKEN` | your bot token from BotFather |
   | `FRONTEND_URL` | `https://alijenta.vercel.app` (step 4; update it if Vercel gives another name) |
   | `GOOGLE_REDIRECT_URI` | `https://alijenta-api.onrender.com/oauth/google-calendar/callback` |

   `JWT_SECRET` and `SECURITY_ENCRYPTION_SECRET` are generated by Render.
   Never change `SECURITY_ENCRYPTION_SECRET` / `_SALT` later: stored e-mail passwords are
   encrypted with them.
3. Service → **Environment → Secret Files** → add `credentials.json` with the content of the
   Google OAuth client JSON (the file from `src/main/resources/google/`).
4. Wait for the first deploy (a few minutes, the free CPU is slow), then open
   `https://alijenta-api.onrender.com/actuator/health` → `{"status":"UP"}`.

Later deploys are automatic: every merge into `main` deploys after CI is green.

## 4. Frontend: Vercel

1. <https://vercel.com> → sign in with GitHub → **Add New → Project** → import this repository.
2. **Project Name**: `alijenta` (this gives `alijenta.vercel.app`; if it is taken, use
   `alijenta-app` and update `FRONTEND_URL` on Render).
3. **Root Directory**: `frontend`. Framework preset: Vite (detected automatically).
4. **Environment Variables**: `VITE_API_URL` = `https://alijenta-api.onrender.com`
5. **Deploy**. `frontend/vercel.json` sends every route to `index.html`, so refreshing
   `/tasks/5` works.

## 5. Google Calendar

In <https://console.cloud.google.com> → **APIs & Services**:

1. **Credentials** → your OAuth client → **Authorized redirect URIs** → add
   `https://alijenta-api.onrender.com/oauth/google-calendar/callback`.
2. **OAuth consent screen** → **Publish app** (status *In production*).
   ⚠️ While the app is in *Testing*, Google refresh tokens expire after **7 days** and the
   calendar integration silently stops working. Visitors will see the "Google hasn't verified
   this app" screen: that is expected for a demo (Advanced → continue).

## 6. Monitoring

### UptimeRobot (primary, every 5 minutes)

1. Sign up at <https://uptimerobot.com>.
2. **Add New Monitor** → type **HTTP(s)** → URL
   `https://alijenta-api.onrender.com/actuator/health` → interval **5 minutes**.
   The endpoint answers `503` when the database or Dropbox is down, so a plain HTTP monitor
   is enough. These requests also keep the free Render service from sleeping.
3. Add a second HTTP(s) monitor for `https://alijenta.vercel.app`.
4. Alert contact: your e-mail (default). Optionally install the mobile app for push alerts.

### GitHub Actions (daily, deeper)

Repository **Settings → Secrets and variables → Actions → Variables**:

| Variable | Value |
|---|---|
| `API_URL` | `https://alijenta-api.onrender.com` |
| `FRONTEND_URL` | `https://alijenta.vercel.app` |

Then **Actions → Live demo smoke test → Run workflow** once to check it is green.

## Known limitations of the free setup

- **E-mail notifications do not work on the demo**: Render free instances block outbound SMTP
  (ports 25/465/587), so `EMAIL_ENABLED=false`. They work locally and on a paid instance.
- **Demo data is reset daily at 03:00 UTC**: every change made by visitors disappears. This is
  intentional, so the next visitor always gets a working demo.
- The first deploy and restarts are slow (around a minute or more) on the free CPU.

## When something is down

| Symptom | Where to look | Usual fix |
|---|---|---|
| UptimeRobot: backend DOWN | Render → service → **Logs** | Look for `Dropbox health check failed` or database errors |
| Dropbox DOWN | Logs: `Dropbox health check failed` | The refresh token was revoked: repeat step 2 and update the variable |
| Database DOWN | Logs: `Communications link failure` | TiDB console: cluster state / quota |
| Login works, calendar fails | Logs: Google `invalid_grant` | Consent screen is back in *Testing*: publish it (step 5) |
| Frontend loads, every request fails | Browser console: CORS error | `FRONTEND_URL` on Render must equal the Vercel URL exactly |

## Plan B: moving the backend

The backend is a plain Docker image configured only by environment variables. If Render
changes its free plan, any Docker host works: create a service from the `Dockerfile`, copy the
variables from section 3, update `VITE_API_URL` on Vercel, the Google redirect URI and the
UptimeRobot URL. The database and Dropbox stay as they are.

## Local production-like run

`docker compose up --build` runs the same image with the `prod` profile and a local MySQL.
Copy `.env.template` to `.env` and fill it in first.
